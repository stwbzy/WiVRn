# WiVRn FSR Runtime v0.3.0

This is the first stable packaging release of the enhanced WiVRn fork. The
native 1:1 path, Meta compositor scaling, lightweight SGSR1, connection
recovery and supervised FBT-E are the supported baseline. Color-only frame
synthesis is included for continued testing, remains explicitly experimental
and is **Off** by default.

## Highlights

- Meta compositor scaling for Quest, with separate game/stream and OpenXR
  target resolutions, compositor filter selection and automatic fallback.
- Lightweight mobile SGSR1, existing FSR1 and NIS choices, fused bilinear
  defoveation, and a 10% threshold that avoids wasteful reconstruction.
- A 180-frame scaling watchdog that falls back without overwriting the saved
  preference or disconnecting the session.
- Experimental color-only frame synthesis with Off/Auto/Always policy,
  headset SSW-like and server optical-flow backends, scene-cut/confidence
  rejection, deadline watchdogs and safe return to real frames plus headset
  ATW. This is not Meta Application SpaceWarp and uses no game depth or motion
  vectors.
- FBT-E profiles and per-body-part selection, prediction controls, dropout
  filtering, a server supervisor, epoch-based reset/acknowledgement and a
  headset reset action. Legacy body-tracking configuration is migrated without
  losing the selected profile.
- Safer runtime ownership, authenticated connection generations, reconnection
  handling and diagnostics for OpenXR/XRizer launches.

## Compatibility and behavior

- The headset APK and PC streamer must come from this same release.
- Legacy `fps_divider=2` is migrated to frame synthesis Off; it is never
  silently re-enabled.
- Switching frame-synthesis backend can briefly rebuild the stream and show a
  black view. Tracking and the connection remain alive during the transition.
- Synthetic frames are encoded and transmitted at the headset cadence; frame
  synthesis reduces application rendering work, not network bandwidth.
- Native 1:1 with frame synthesis Off remains available as the recovery path.

## Artifacts

- `WiVRn-fsr-runtime-v0.3.0-quest-arm64.apk`: optimized, installable Quest APK
  using the fork package ID `org.meumeu.wivrn.github`.
- `WiVRn-fsr-runtime-v0.3.0-linux-x86_64.AppImage`: portable PC streamer.
- `WiVRn-fsr-runtime-v0.3.0-linux-x86_64.flatpak`: Flatpak bundle containing
  the PC dashboard/server integration.
- `WiVRn-fsr-runtime-v0.3.0-linux-x86_64.tar.gz`: portable server tree and
  licenses, provided alongside the AppImage.
- `SHA256SUMS`: checksums for every downloadable artifact.

The APK is signed with the fork's development certificate so it is directly
installable. Android will require uninstalling a package with the same ID if
that existing copy was signed by a different certificate; doing so clears that
package's local settings.

## Verification completed

- Release server build and all nine local unit/integration tests.
- Optimized Android release build and APK signature verification.
- Physical Quest 3S streaming, live option changes and FBT-E validation by the
  project owner, with no additional errors in the final test pass.
- Automatic frame-synthesis and scaling fallbacks without a headset disconnect
  or permanent black screen.

SSW/ASW remains experimental pending broader Quest 2, multi-GPU and prolonged
network/encoder coverage. The rest of the release is stable and does not
enable that path without user consent.
