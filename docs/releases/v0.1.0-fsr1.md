# WiVRn FSR Streamer Preview 1

This is the first prerelease of the WiVRn FSR fork. It combines experimental
FSR 1 spatial upscaling with the existing color-only frame-generation path and
includes the connection-lifecycle and virtual body tracker fixes developed on
the `feature/fsr-frame-generation` branch.

## Highlights

- FSR 1 EASU upscaling followed by RCAS sharpening in the server compositor.
- Combined FSR upscaling and frame generation, including 45 to 90 Hz and 60 to
  120 Hz transport modes.
- Explicit connection states and a 30-second reconnection window after an
  unexpected headset disconnect.
- Virtual body tracker configuration is applied independently of the OpenVR
  compatibility layer selected by the application.
- Updated WiVRn interface and documentation for the experimental features.

## Assets

- `WiVRn-fsr1-v0.1.0-android-arm64-debug.apk`: signed debug APK for testing.
- `WiVRn-fsr1-v0.1.0-linux-x86_64.tar.gz`: Linux x86_64 server test bundle.
- `SHA256SUMS`: SHA-256 checksums for both downloads.

The Linux bundle is not a distribution-independent AppImage. It may require
compatible system Vulkan, VA-API, PipeWire and runtime libraries. The source
archives generated by GitHub are the canonical portable distribution.

## Install the headset client

Remove a mismatched WiVRn build if Android rejects the signature, then install
the APK:

```sh
adb install -r WiVRn-fsr1-v0.1.0-android-arm64-debug.apk
```

The client and server in this release must be used together because the
protocol changed.

## Run FSR and frame generation together

From the extracted Linux bundle, or with equivalent paths from a local build:

```sh
XRT_PRINT_OPTIONS=1 XRT_LOG=info \
WIVRN_FSR_UPSCALING=1 \
WIVRN_FSR_SHARPNESS=0.2 \
WIVRN_FSR_FRAME_GENERATION=1 \
WIVRN_FSR_FRAME_GENERATION_COLOR_ONLY=1 \
WIVRN_FSR_FRAME_GENERATION_HANDOFF=1 \
WIVRN_FSR_FRAME_GENERATION_DOUBLE_RATE=1 \
./usr/bin/wivrn-server --no-fork --early-active-runtime
```

Use a render scale around 70-85% for the first test. Disable Application
SpaceWarp on the headset when using server-side frame generation; otherwise a
120 Hz headset can be reduced twice and the log may show an unintended 30 Hz
application rate.

## Validation and limitations

- Server unit tests, shader validation and APK v2 signature validation pass.
- The frame-generation path is color-only and does not yet use application
  depth or motion vectors, so disocclusion artifacts remain possible.
- Combined FSR and frame generation is experimental and still requires broad
  physical headset/GPU testing; this is intentionally marked as a prerelease.
- OpenComposite or xrizer selection affects OpenVR application compatibility,
  not whether WiVRn exposes its virtual body trackers.

See [FSR frame generation](https://github.com/AsagiAsagiri/WiVRn/blob/v0.1.0-fsr1/docs/fsr-frame-generation.md),
