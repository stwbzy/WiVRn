# WiVRn Quest Compatibility Preview

This pre-release introduces an opt-in Quest compositor route, lightweight
SGSR1 and experimental server runtime frame synthesis.

Status date: 2026-08-13. This file describes the current candidate, not a
published stable release.

## Highlights

- Separate game render and OpenXR target resolutions.
- Meta compositor mode recommended for Quest 1 and Quest 2.
- Qualcomm SGSR1 mobile reconstruction fused with client defoveation.
- Existing FSR1 retained; Native and fused bilinear remain safe routes.
- Off/Auto/Always server frame synthesis using portable hierarchical Vulkan
  optical flow, without VRChat changes or AppSW metadata.
- Automatic session-only fallback plus separate scaling and synthesis
  telemetry.
- Legacy `fps_divider=2` configurations migrate safely to Off.

Client and server must be upgraded together because the wire protocol changed.
All new modes are opt-in and runtime frame synthesis remains experimental.

## Current physical result

- A matching debug APK and server entered VRChat VR mode through XRizer on a
  Quest 3S at 72 Hz.
- Always mode paced VRChat at 36 Hz and encode/transport at 72 Hz and
  dispatched 182 hierarchical optical-flow candidates.
- Missing shards and stale intervals then exceeded the encode/network budget.
  The watchdog disabled synthesis until reconnect and restored 72 Hz real
  frames without disconnecting or showing a black screen.
- With synthesis Off, measured latency was 50-60 ms in WayVR and usually about
  71 ms in VRChat, with normal head motion.
- Meta compositor scaling worked but looked more pixelated than SGSR1 in the
  aggressive 80% render to 119% target test. A matched-resolution/filter
  comparison is still required.

## Known issues and safeguards

- Always mode is not ready for normal use at the tested 10-bit, 50 Mbit/s
  configuration. Use Off as the stable baseline; Auto remains experimental.
- A cream/purple right-eye tint seen in an earlier Always run has not yet been
  closed by sustained stereo validation.
- Frame synthesis does not reduce bandwidth because synthetic frames are also
  encoded and transmitted.
- The active-runtime and feedback-generation races found during physical
  debugging are fixed in the current source and server build. A rejected
  second server can no longer remove the first server's OpenXR manifest.
- Quest 2, Quest 3S at 90 Hz, two-hour endurance and multi-vendor GPU coverage
  remain release blockers.

See [Quest compositor scaling and runtime frame synthesis](../fsr-frame-generation.md)
for behavior, limitations and the required physical acceptance matrix.
